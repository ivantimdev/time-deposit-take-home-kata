# Step 7 — GitHub Actions: verify, lint, guard rails, mutation, publish image

Read `AGENTS.md` and the reports of steps 5–6. Pre-flight: `gh auth status` succeeds for the
`origin` repository, `docker info` works. You **may push** to `origin main` in this step, and
you must: the definition of done is a green run on GitHub.

## Workflow `.github/workflows/ci.yml`

Triggers: `push` (all branches and tags `v*`), `pull_request`. `permissions: contents: read,
packages: write`. `concurrency` per ref. Jobs:

1. `verify` — `ubuntu-latest`; `actions/checkout` with `fetch-depth: 0` (guard rails read
   history); `actions/setup-java` Temurin **17** with Maven cache; `cd java && ./mvnw -B spotless:check verify`
   (Testcontainers works on the hosted runner's Docker); upload `java/target/site/jacoco`
   and `java/target/failsafe-reports` as artifacts.
2. `contract-lint` — `actions/setup-node` 20; `npx -y @stoplight/spectral-cli@6 lint java/src/main/resources/openapi/openapi.yaml`.
3. `sanitize` — Java 17; `cd java && ./mvnw -B -Psanitize rewrite:dryRun`.
4. `guardrails` — `scripts/guardrails.sh` (no extra patterns in CI).
5. `mutation` — Java 17; `cd java && ./mvnw -B -Pmutation test-compile org.pitest:pitest-maven:mutationCoverage`;
   upload `java/target/pit-reports`.
6. `publish-image` — `needs` all of the above; runs only on `push` to `main` or a tag `v*`
   (not on PRs); `docker/login-action` to `ghcr.io` with `GITHUB_TOKEN`; `docker/metadata-action`
   with image `ghcr.io/${{ github.repository_owner }}/time-deposit-kata` (owner lowercased by
   the action) and tags: `type=sha,prefix=sha-` on `main`, `type=semver,pattern={{version}}` and
   `latest` on `v*` tags; `docker/build-push-action` with `context: java`, `push: true`,
   GitHub Actions cache (`cache-from/to: type=gha`).

Pin every action to a major version tag (`@v4`, `@v5`, …), current as of today. Keep the
file readable: no matrix, no reusable workflows, no secrets beyond `GITHUB_TOKEN`.

## Commits and pushes

1. `ci(repo): run build, tests, lint, guard rails and mutation on push` — jobs 1–5.
   Push. `gh run watch --exit-status` (or `gh run list` + `gh run view`) until green. Fix
   forward with new commits (`fix(repo): …` or `ci(repo): …`) — never amend. Each fix: `/verify`
   locally first.
2. `ci(repo): publish the container image to github packages` — job 6. Push, watch, confirm the
   `sha-…` image exists: `gh api /users/<owner>/packages/container/time-deposit-kata/versions`
   or `docker pull ghcr.io/<owner>/time-deposit-kata:sha-<short>` after `docker login ghcr.io`
   with `gh auth token`.
3. Tag `v0.1.0` (`git tag -a v0.1.0 -m "v0.1.0"`; the tag message is exempt from the commit
   convention), push the tag, watch the run, confirm `0.1.0` and `latest` exist.
4. `docs(repo): add build status badge and container image link` — badge for `ci.yml` on
   `main` and a line in README "How to run" offering `docker pull ghcr.io/<owner>/time-deposit-kata:latest`
   as an alternative to building locally (with a `compose.yaml` comment showing how to switch
   `build:` for `image:`). Push, watch.

Tell the developer at the end: the GHCR package is private until they set it to public in
the package settings on GitHub (one click); until then the pull line in the README only works
authenticated.

## Verification before you finish

1. `gh run list --limit 5` shows the latest runs for `main` and `v0.1.0` as `completed success`.
2. `gh api` (or `docker pull`) proves the three tags (`sha-…`, `0.1.0`, `latest`).
3. Local `/verify` green at HEAD; `scripts/guardrails.sh` green over the new commits.
4. Report `prompts/reports/07-ci.md`: commits, run URLs, durations per job, image digest,
   anything you had to fix forward and why.
